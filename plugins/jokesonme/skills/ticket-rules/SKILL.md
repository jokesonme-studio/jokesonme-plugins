# 替看我笑話開票

票開出來是要給夥伴（和夥伴的 Claude）照著做的。寫不清楚，接手的人就會做錯。所以開票前一定照下面四步，不要跳步。

## 1. 問清楚四段

描述固定四段，每段都要有實際內容：

- **現在怎樣**：現在的畫面或流程哪裡不好用、出了什麼錯。bug 要寫怎麼重現。
- **希望變成**：做完之後應該是什麼樣子。
- **做完看得到什麼（驗收）**：一條一條寫「做完看得到的事」，開票的人之後就照這幾條驗收。不能寫「正常運作」這種看不出有沒有做到的句子。
- **誰會用、誰看得到**：管理員、成員、財務夥伴，或觀眾。

使用者沒講到的段落，用一兩個具體問題問他，不要自己編。一次問完，不要一段一段來回。

分類四選一：新功能、修 Bug、改善流程、修正資料。標題 120 字以內，一句話講清楚要改什麼。

## 2. 查有沒有重複

用 `list_tickets` 看進行中的票。有看起來在講同一件事的，把那張票號給使用者看，問他要開新的還是補在那張（補內容請他到網頁上編輯，或在那張票上留言給接手的人）。

## 3. 列出完整草稿

照這個格式整段列出來，請使用者確認或修改：

```
標題：…
分類：…
描述：
現在怎樣：
…

希望變成：
…

做完看得到什麼（驗收）：
1. …
2. …

誰會用、誰看得到：
…
```

## 4. 使用者說好才開

使用者明確說「好」「開」「可以」才呼叫 `create_ticket`。他要改就改完再列一次。開好後把票號和網址告訴他。

## 其他動作

認領、交付、驗收、退回、不做也一樣：呼叫 `act_on_ticket` 前先說要對哪張票做什麼，使用者同意才做。退回和不做一定要問原因。

工具回「這台電腦還沒連結看我笑話」時，把那段說明原樣告訴使用者；他貼出「連結看我笑話，代碼 jk_link_…」就呼叫 `link_account`。
